# 下一阶段开发计划

2026-10-25，根据用户讨论确定。先做功能，UI 后做多版预览，再讨论落地。

## 1. 本地备份与恢复

状态：已完成首版，含手动备份、每日启动自动快照、恢复预览和恢复前安全备份；历史备份保留策略后续补充。

将数据库、菜谱封面和步骤图一起打包，支持手动备份、自动备份和恢复预览。备份使用 SQLite 一致快照，恢复前校验内容并备份当前数据；失败时保留原库。API 密钥不混入普通备份。

验收：临时数据完整备份后可恢复，图片与引用一致；损坏包、版本不兼容和中断不破坏现有数据。

## 2. 用餐人数与自由文本偏好

状态：已完成，与统一设置弹窗一同实现；详见 [设置说明](SETTINGS.md)。

设置默认用餐人数，用于菜谱详情初始份量、平常配餐和 AI 配餐。保留菜谱原标准人数，不改写配方和历史菜单；当次指定人数优先。

口味、忌口、厨具等由用户自由输入文本，支持修改和清除，AI 回答与配餐时参考。临时聊天要求不自动变成永久偏好。

验收：重启保留设置，详情和配餐用量一致；AI 能收到偏好，当前要求可覆盖默认值。

## 3. 内置食材名称表

内置覆盖常见中文食材的规范名与别名表，例如番茄＝西红柿。识别和导入菜谱时使用统一名称，同时保留来源原文；手动输入别名时提示是否修改，也允许保留。

明确同义词可归并，形态、品种和单位差异不强行合并。已有数据整理先展示影响，保护库存批次、历史配方与菜单引用。

验收：常见别名能匹配；不同食材不误合并；不重复生成采购，不无依据换算数量。

## 4. 烹饪回顾

结合实际烹饪记录和厨房手记生成可编辑回顾，用户也能自由编写。AI 参考近期做过的菜与调整意见，减少重复配餐。计划、手记和实际烹饪分开，写回顾不扣库存。

验收：回顾来源可追溯，手动内容可编辑删除；AI 可参考真实近期记录，不把未完成菜单当作已做过。

## 5. Firebase 云备份与同步

状态：可选云备份首版已接入，独立项目 `chefish-kitchen` 的香港免费数据库、权限、索引与普通邮箱密码登录已配置，本地 Web App 配置已写入。真实云端合成账户传输、分块复用、未验证邮箱和跨账户拒绝验证通过；原生完整往返与双机验收待完成。详见 [账户与云备份](CLOUD_SYNC.md)。当前实现不依赖付费 Storage。

多设备修改需要操作去重、版本与冲突处理，不能直接相互覆盖数据库或依赖最后写入覆盖库存。图片去重，凭据默认不上传。先验证目标 Windows WebView2、用户实际网络和费用配置。

已只读参考 `E:\zenfish` 的账户、权限和网络配置，没有复制其项目凭据，也没有修改其文件或云端配置。用户已重新登录 CLI，并在控制台完成 Firebase Authentication 首次初始化；配置确认 subtype 为 FIREBASE_AUTH，未启用计费。Chefish 的库存、采购与烹饪自动同步仍须保留本地事务，不能把整库覆盖称作自动合并。
