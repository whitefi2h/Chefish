# 厨房设置

点击左下角“我的厨房”打开设置。弹窗使用左侧分类、右侧内容的布局，默认显示用餐与偏好。备份与恢复放在此处，主导航保留日常厨房功能。

| 分类 | 当前设置 |
|---|---|
| 用餐与偏好 | 默认用餐人数；口味、忌口与饮食要求、厨房与厨具的自由描述；各项可修改或清空 |
| 通用 | 重新开始初始化；下次启动时打开的页面；Enter 或 Ctrl+Enter 发送消息 |
| AI 助手 | DeepSeek、OpenAI、Gemini 模型配置、密钥管理与连接测试 |
| 数据与备份 | 每日启动自动备份开关；本机备份位置和最近保存时间；手动备份、恢复预览与确认 |
| 账户与云端 | 云服务配置状态；配置后支持邮箱账户、验证、上传、下载预览与确认恢复 |
| 关于 | 程序版本、数据保存方式与模型调用说明 |

用餐、偏好和通用设置点击“保存设置”后生效；启动页面在下次启动时使用。模型配置在 AI 助手页单独保存。关闭含有未保存修改的弹窗时会提醒。

## 人数与偏好的使用

菜谱详情初次打开时按默认人数展示用量，原配方的标准份数保留。用户在详情页选择的人数会带入新增菜单表单；从菜单页面新增或拖入菜谱时使用默认人数，仍可当次调整。移动和编辑已有菜单保留原人数，修改默认值不重写历史数据。

AI 回答和安排新菜单时会收到默认人数、口味、忌口、厨具描述。本次明确要求优先，临时聊天内容不会写为永久设置。偏好通过设置或初始化向导中的明确保存操作生效。

## 初始化

空白厨房首次启动会打开初始化向导。已有厨房可从“通用 → 重新开始初始化”进入，预填现有配置，不重置数据。

流程依次为欢迎、模型连接、饮食偏好、常吃菜系、厨房管家、云账户和完成；每步都可跳过。关闭后已保存的配置保留，意外退出应用后可恢复步骤。AI 整理偏好由用户主动触发，先展示可编辑草稿，再由用户保存。选择菜系只调整统一目录中的菜系开关。

云账户步骤只处理注册、登录和邮箱验证，不自动上传、绑定或替换厨房。流程进度仅存在本设备；API key 仍使用原有凭据保存机制，不写入流程进度。

设计与验收见 [初始化方案](ONBOARDING_PLAN_20261103.md) 和 [实施记录](ONBOARDING_IMPLEMENTATION_20261103.md)。

## 数据保存

用餐偏好和通用设置保存在本机业务数据库，包含在普通备份中。模型配置和密钥沿用 Windows 凭据管理器保存，不包含在普通备份中。浏览器演示的设置只在当前会话有效。

自动备份在每日首次启动时保存；恢复前始终另存安全备份，独立于每日自动备份开关。当前保留历史备份，不自动清理。点击文件夹按钮可打开备份目录。

## 后续设置的顺序

- 外观：待整体界面预览确定后，再加入一致的字号与主题选项。
- 备份保留：先提供历史列表和占用大小，再加入保留数量与可确认的清理操作。
- 多设备同步：先完成独立云项目部署和真实双机云备份验收，再加入版本冲突与事务同步。详见 [账户与云备份](CLOUD_SYNC.md)。
- 程序更新：待签名、升级和数据保留专项验收后，接入更新检查与自动更新。

尚未实现的能力不显示为可用开关。
