# 下厨房读取修复 · v2.4.1

用户提供的107076587、107431912两个链接在普通HTTP读取时均返回302，跳转到/auth/humancheck_captcha/，没有正文。原导入将其统一报为网站拒绝；站内搜索也会遇到同类跳转。

## 处理方式

- 读取链接或搜索遇到验证跳转时，使用现有应用确认弹窗提示“打开下厨房”。站点窗口中由用户完成验证，返回Chefish点击“继续读取”，从该窗口当前DOM读取页面，仍进入原有可编辑预览，不自动保存。取消保留输入和旧草稿。
- 下厨房窗口独立保存站点会话，后续打开复用；不复制外部浏览器Cookie，不自动处理验证码。关闭或取消后仍可重试。
- 只允许已列明的下厨房站内主机导航；读取时再次检查页面地址与本次菜谱ID或搜索词一致。验证页、其他菜谱、站外页和不匹配的读取方式不能作为目标结果。远程站点窗口没有厨房IPC能力，新增读取命令也只接受main窗口发起。
- 站内结果最多保留50条，助手首批数量不变，新增“更多本页结果”展开尚未显示的候选，不重复请求网站；本次没有声称支持跨页搜索。备用搜索仍使用原DeepSeek接口，缺少密钥会明确解释，不把模型配置问题伪装成站点无结果。
- 补齐JSON-LD @type数组、已确认的hanwuji站内别名，以及reqwest Windows系统代理特性。只在没有菜谱正文时识别验证页，避免正常页面里的验证脚本链接造成误判。

## 验证

- Rust常规套件179项通过；原生WebView2专项1项通过。原生专项使用隔离应用标识、本地HTTP合成页面与隐藏窗口，验证实际eval回调能读取DOM且远程页面调用厨房命令被拒绝，不访问个人厨房。
- 浏览器IPC fixture累计24项相关场景通过，覆盖读取后预览、取消不打开不保存、搜索验证续读、展开更多结果不重发网络请求，以及原有导入和助手回归。首次新增测试曾因相邻确认弹窗的测试等待方式失败，修正测试后通过。
- TypeScript和ESLint检查通过。正式Windows构建、签名与公开更新入口状态见release-v2.4.1.json。
- 没有替用户完成下厨房真实验证码，没有将合成页面验证写成两个真实链接已导入成功。网站仍可能拒绝访问；可沿用本地HTML导入。未执行用户真实覆盖安装。
