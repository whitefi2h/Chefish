# 粗略计量接入记录 · v2.4.0

日期：2026-11-21。保留精确模式，复用原库存、完成烹饪、采购和通用设置页面。

## 最终行为

- 库存原数量栏使用紧凑渐变拉杆，连续拖动、松手吸附，键盘可调；左侧灰色按钮标记用完。不增加状态列及拉杆下方重复标签。
- 开启粗略模式不按统一克数批量猜档位；旧精确批次显示未估计，用户调节后档位成为当前记录。旧数字保留为历史，粗略库存与 AI 不把它当作当前数量。
- 完成烹饪默认直接调剩余状态，手动选择优先；请求发出后的手调也受到保护。AI建议只填未手调项目；配方外的明确食材也会追加拉杆供核对。确认不自动调用或等待AI，识别失败仍可保存。
- 原采购列表只替换购买动作：打勾即完成购买和收货，记录本地当天，单独新批次默认充足；不需要表单。原食材及所需数量继续显示，撤销沿用原收货与采购流水。
- 新批次库位未指定、真实到期日为空；下次整理按用户自动整理与估算偏好补充推测库位、预计复查日期，不覆盖用户信息或伪造包装保质期。
- 粗略采购不扣除旧精确数量，也不把档位转成克数；按配方保留参考采购量。充足/盈余只在同一食材一两次短期安排、人数未超过标记参考人数、日期适用时暂不重复补货；更多安排保留需买量，不能当成无限库存。
- 切回精确模式不会复活已经失效的旧数量；批次详情补填真实当前数量后恢复数字记账。

## 数据与兼容

schema 19 新增 inventory_measurements 和 inventory_measurement_events，关联原批次及不可变库存事件。level=-1用完、0缺乏、1充足、2盈余；不存在档位记录的批次仍为原精确记录。每次档位修改共享批次 version，记录前后状态及参考人数。新档位批次的旧数值列仅满足原表约束，不向当前数量、AI和采购抵扣暴露。

烹饪与档位修改在同一事务保存；撤销恢复前状态并保留后续版本检查。收货有请求幂等保护。新表进入增量同步白名单、快照、备份与恢复；计量模式加入共享偏好，同字段沿用现有最后同步修改策略。旧四字段偏好重放时保留新增模式。迁移前自动保存安全备份。

v2.3.12及更早客户端无法写入或恢复 schema19 操作；所有同步设备需升级。生产规则必须先支持 schema19，再公开 Release。
