## 2. 最近处理的问题：冲突导致同步卡住

用户截图为 v2.2.0：账户与云端显示“需要处理同步冲突”，132 项本机操作待同步，原因是“两台设备修改了同一项厨房偏好”。界面有“备份本机并保留云端”和“立即同步”。

发现两个原因：

1. 人数、口味、忌口、厨具作为一个整体 JSON 比较。两台设备修改不同字段也会触发冲突。
2. `syncRuntime.retry()` 只调用后台 tick，而 tick 遇到已有冲突标记直接返回，导致“立即同步”没有真正重试。

### 已实现

- 偏好应用四个字段的差量，保留无关字段。相同字段以云端全局操作顺序中最后同步的修改为准，不依赖设备时钟。
- 应用云端修改后重放本机待上传操作；单独持久化本机回退基线，确保下一轮倒退、重启或明确选择云端恢复时能还原正确内容。
- **已发布或待确认的上传载荷不改写**，防止确认丢失后的同 ID 哈希不匹配。
- 手动重试通过原生 `sync_retry` 清除冲突标记，再执行实际同步。需验证账户且与厨房绑定匹配；不丢弃队列、不自动恢复暂停状态。
- 后台唤醒仍不自行解除冲突。库存等行记录发生真实冲突时继续事务回滚、暂停并保留本机内容。
- 明确选择“备份本机并保留云端”仍会先做安全备份，再撤销**全部**本机待同步操作；页面说明已写清这一点。不要替用户点击该按钮来清空 132 项队列。

### 主要源码

| 路径（相对工作区） | 作用 |
| --- | --- |
| `src-tauri/src/db/replication.rs` | 偏好字段合并、队列倒退与重放、手动 retry、冲突处理 |

| `src-tauri/src/db/replication_tests.rs` | 原生同步回归及隔离测试桥接 |

## 5. 本轮之前已经完成的产品改动

v2.2.0 已发布的范围包括：全局 UI 视觉升级、四类菜谱标签、本地食材彩色图标、每周灵感按周隔离、可跳过/重开的初始化、启动 Loading 与舒缓动效。以下为后续修改应遵守的用户决定：

- 保持现有核心面板与功能结构；不要因 UI 调整重写 AI、库存、同步或调度逻辑。
- 明亮橙色加浅绿辅助，Logo 允许改色但图形不变。思源黑体的 Semibold 标题/强调、Medium 正文为用户最终采用方向；字号、间距需实机微调，不能只改常态可见页面。侧栏“好好吃饭”使用细衬线体。
- 菜谱宽屏四列、窗口三列；周灵感按钮在菜名右侧且易识别，避免突兀实心橙。卡片标签分色，布局紧凑。
- 标签分为菜系、菜品特性、烹饪方法、自定义。菜系主分中餐、西餐、异国风味，删除过细的中餐三级/东南亚二级预设。默认显示中西餐，其他按用户开关。允许自定义、层级、批量全选/反选、开启/关闭/删除/合并。
- 管家从受控标签目录选择，不维护独立自由文字标签；可设置是否允许助手自动开启匹配的现有标签。卡片标签按类别配色，导入编辑默认收起标签列表。
