# 第二轮 UI 重构检查清单（待用户确认）

依据：《Chefish UI 视觉修改建议 V1.0》、当前样式与页面代码、第一轮截图和用户实机反馈。此文件是待确认的修改范围，不是完成记录；本轮尚未修改应用代码。

上一轮主要落实了封面比例、部分边框减重、库存提醒与周历交互。字体、正文尺寸、页面视觉主次与工具区组织仍未完整落实。用户已确认库存轮播、拖放反馈和去掉重复完成标签，继续保留。

## 必须纠正的两项

* \[ ] R01｜列数以真实桌面窗口为准：正常最大化四列，普通窗口三列；检查 Windows 缩放与 WebView 实际可用宽度，不能再把固定浏览器宽度测试当作验收。极窄窗口的文字、按钮不能重叠。原实现是按视口宽度断点切列，并未实现严格的窗口状态语义；用户实测未达标，原因待现场核查。
* \[ ] R02｜周灵感按钮保留菜名右侧。未加入：浅橙底、深橙字及细描边；已加入：浅绿底、深绿字和勾选。保留按钮轮廓、可见文字和点击区域，取消当前每卡一块高饱和实心橙。具体颜色在真实菜谱照片上检查。

## 全局规范（原方案第 2、4 节）

* \[ ] G01｜统一中文字体：采用随应用提供的 MiSans，先核验许可与分发方式；Logo 字标保持原样。当前系统字体栈不等于已落实原方案指定字体。检查中文、拉丁字母、数字及各字重的实际渲染。
* 用户批注：几个备选字体都可以试试，到时候看视觉效果决定。
* \[ ] G02｜建立文字层级：页面标题约 30px，内容区块标题 20–22px，菜名 17–18px，正文 14–15px，辅助信息 12–13px。密集表格正文 13–14px，主要信息不使用 9–11px。工具区标题可用 18px，不把所有标题机械放大。
* 用户批注：大小不定死，到时候根据视觉效果调整。
* \[ ] G03｜统一字重、行高和对比度：正文约 1.55；名称、数量与关键日期优先；说明使用中灰。减少整页粗体、浅灰小字和橙色文字链接。
* 用户批注：同上。
* \[ ] G04｜完整落实三层容器：主面板白底，辅助区浅底无重描边，普通内容行依靠对齐和分隔。逐块移除多余内框，不只调整边框色值。
* \[ ] G05｜统一间距与圆角：页面边距约 32px、模块 24–32px、面板内距 20–24px；主面板 18–20px、控件 10–12px、标签 6–8px。小窗口作受控收缩，保留操作密度。
* 用户批注：同上，大小不定死。
* \[ ] G06｜统一按钮、标签与状态：页面级主要操作才用实色橙；重复行内操作采用浅底或中性样式；标签缩小填色面积；图标不必个个带外框。悬停、焦点、禁用、选中、危险状态跨页面一致。
* \[ ] G07｜重整标题区：库存、周菜单、采购采用短标题和紧凑工具区；首页与菜谱保留内容感。减少英文眉题和重复宣传式描述，使内容更早进入首屏；不对所有页面套同一头部。

## 首页（原方案第 3.1 节）

* \[ ] H01｜下一餐形成明确主视觉：重新分配现有面板比例、图片与菜名尺寸，而不是只把图片加高；保持既有模块、顺序及同餐多菜显示。
* \[ ] H02｜库存提醒、周安排与采购摘要统一降级：压缩重复说明和空白，以紧凑内容行、少量关键数值和轻入口呈现；时间、人数整理为一组元数据。
* \[ ] H03｜缩短顶部装饰区：标题和下一餐之间不留过长空白，默认窗口首屏能同时理解下一餐及其他管理信息。

## 菜谱库与详情（原方案第 3.2 节及内容页原则）

* \[ ] L01｜在 R01 的四列／三列基础上调整卡片密度：保留 4:3 封面；菜名最多按合理行数展示，长名称能查看完整内容；不能为了右侧按钮把标题挤成很窄一列。
* \[ ] L02｜统一封面容器内裁切与缺图表现：用户原图保持不变，不擅自替换、去水印或裁掉原始数据；拼接照片无法靠统一裁切完全修复时，保留用户更换封面的现有入口，不承诺自动修图。
* \[ ] L03｜简化信息层级：照片与菜名为主；时间、人数、分类、收藏为辅；描述继续留在详情。弱化卡片外框，避免大标签、元数据和按钮争抢照片。
* \[ ] L04｜搜索、分类、排序和管理入口重组为紧凑工具区；统一底部查看入口，和 R02 的右侧主卡片操作分工明确。
* \[ ] L05｜详情形成清晰阅读顺序：主图与标题优先，配料、步骤和手记统一排版；保留现有分栏与窄窗口回落，不新增信息模块。步骤图片保持既有展示逻辑。

## 库存（原方案第 3.3 节）

* \[ ] I01｜保留已认可的关注轮播，进一步统一摘要、计数和轮播按钮对齐；有溢出时可操作，到边界禁用，不恢复滚动条与列表查看入口。
* \[ ] I02｜压缩搜索与筛选层级：减少工具区纵向叠层和标签底块，选中态明确；不移除分类、多选筛选和显示已用完功能。
* \[ ] I03｜重排表格列宽：名称、数量、到期日期优先；常规行高约 52–60px。默认桌面窗口尽量无需横向滚动，必要时仅表格局部滚动，不能挤坏控件。
* \[ ] I04｜强化名称、数量、日期的可读性，弱化批次说明和次要操作；数量调节、库位编辑保持易发现，不能依赖悬停才出现。
* \[ ] I05｜统一过期／临期／缺货状态：使用文字、图标和克制浅色；保留常备调料独立区域及红色危险语义，避免恢复整行铺红。

## 每周菜单（原方案第 3.4 节）

* \[ ] W01｜整合周切换、日期与采购预览工具区的对齐和换行；灵感保持紧凑单行，让周历成为主要视觉区域。
* \[ ] W02｜统一空格、已排菜卡和同餐多菜的密度：图片高度、菜名、时间人数及完成勾选不互相挤压；保留已认可的空格减重和去掉完成文字。
* \[ ] W03｜补齐拖入目标、悬停、保存中和失败回退的视觉反馈；保持已修正的立即落点显示及原有保存校验。早餐默认隐藏、餐次设置和多菜拖拽不变。

## 采购清单（原方案第 3.5 节）

* \[ ] S01｜待买清单成为视觉中心，调料缺货提示改成轻量摘要，右侧统计只突出待买和已买等关键指标；保留现有面板位置和购买／入库流程。
* \[ ] S02｜已购买项目降低对比度，与待买项目清楚区分；优先沿用现有分组，不先新增折叠交互。
* \[ ] S03｜数量、单位、状态和行内操作对齐，去掉重复徽章与重描边；备忘、复制、导出等辅助操作降低视觉权重，入口仍可见。

## 图标、助手和设置（原方案通用规范及既有边界）

* \[ ] D01｜食材素材统一视觉大小、居中、留白和背景；只做显示规范，不重做映射、不换用户图片、不新增素材体系。首字头像与彩色素材的视觉重量接近。
* \[ ] D02｜助手和设置跟随统一的字体、表单、按钮与间距规范；保留紧凑任务横幅、固定输入框、历史会话、设置分组和单一保存入口。

## 第二轮交付与验收

* \[ ] V01｜先给出菜谱与库存两个样板的实际 Windows 截图，包含最大化与普通窗口、长菜名、真实照片及缺图状态，用户检查后再扩展至其他页面。
* \[ ] V02｜分别检查 Windows 缩放、窗口状态与 WebView 可用宽度；浏览器 1000/1280/1440/1920 检查只作补充。菜谱列数以用户目标桌面环境实测为准。
* \[ ] V03｜完成后逐项记录已完成／未完成／不采用及理由，提供前后截图。回归导航、筛选、库存编辑、菜单拖放、采购、烹饪确认和 AI 提案；检查抽屉开关背景稳定、弹窗底部操作及键盘焦点。

建议执行顺序：R01–R02 与 G01–G07 → 菜谱／库存样板 → 用户确认 → 首页、周历、采购及其余公共组件 → 桌面与交互验收。保留业务逻辑、数据库、AI、同步与调度；本清单批准前不进入实现。
