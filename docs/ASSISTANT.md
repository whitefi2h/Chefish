# AI 助手

助手帮助完成厨房应用中的已有操作。它读取实际数据并提出命令，应用负责验证和执行，不直接操作数据库或系统。

## 配置与数据流

从助手设置选择 DeepSeek、OpenAI 或 Gemini，填写密钥和模型 ID，测试连接。DeepSeek 是当前主要实测服务；适配接口存在不代表所有模型都已实测。

设置与密钥保存在 Windows 凭据管理器，业务 SQLite 不存密钥，界面不回传已保存密钥。相关对话和厨房上下文发送至所选模型服务。下厨房站内读取优先；外部搜索回退当前使用 DeepSeek 搜索服务及其凭据。

## 工作方式

1. 查询使用本机菜谱、库存、菜单、调料、手记和采购结果，必要时读取完整配方或烹饪分配。
2. 修改返回类型化命令，数据库副本试运行后形成提案卡，展示餐次、菜名、人数、补购和实际变化。
3. 用户可同意、拒绝或继续对话调整。补充约束替换未执行提案，发送“确认”不能绕过界面按钮。
4. 执行时再查版本，一批失败整体回滚。删除、丢弃需要额外确认。

执行令牌有效 20 分钟，重启后旧令牌不可执行。聊天自动保存在本机，支持手动清除；历史提案状态不等同于仍可执行。

## 日常请求

- 配餐优先本地菜谱、实际人数、时间和库存，不擅自改成网页搜索。
- “蒜和鸡翅都买了”匹配当前唯一待购项目；未给数量时以待买量提案，不要求用户自己找按钮。
- “醋和蜂蜜买了”更新调料为备有，不问数量和保质期。
- 刚入库后补充日期或库位，优先修改该批次，保留其他字段，不重复新增。
- 明确授权估计储存时间时提出预计复查日期，展示形态、库位与起算依据；未授权且未知时不伪造日期。估计不是食用安全保证。
- 只有无法形成合理提案的关键歧义才追问；用户已回答的问题不重复问。

## 下厨房检索与整理

默认推荐 3 道，明确数量时按要求及来源可得数量展示。优先读取站内结果页，按本页做过人数排序，评分与做过人数分开标注，不宣称是全站热门排行。

候选附原始链接，关联所属回复。整理所选候选时读取正文，保留来源、原用量、步骤、封面与步骤图。页面失败时保留原因，可导入本地 HTML 或粘贴正文，不把摘要当完整原菜谱。

精确单位由代码校验，范围、适量、杯勺等无法准确换算时保留原文。配料表优先于步骤中的重复提及，避免同一份调料重复计量。草稿可编辑，确认后保存。

## 限制

助手没有任意 SQL、终端、文件导出或跨应用权限。部分新建后引用的连续动作需要两轮提案。模型可能误解，网站也可能拦截读取，用户应审核提案。长期饮食偏好和更完整的多步任务仍待开发。
