# 菜谱标签系统接入记录

2026-11-01。入口位于「我的菜谱 → 管理标签」；单份菜谱可在编辑器或详情中的「编辑标签」修改。初始化引导留待下一阶段。

## 已实现行为

| Before | After | Why |
| --- | --- | --- |
| 单选菜谱分类与管家自由标签并存 | 菜系、菜品特性、烹饪方法共用稳定 ID 目录 | 用户和 AI 使用同一套词汇 |
| 封面上叠加分类 | 标签位于菜名下、人数上；前三项加余量提示 | 食物照片完整，文字层级集中 |
| 分类横向单选 | 同类型多选为「或」，跨类型为「且」，上级匹配下级 | 支持实际找菜习惯 |
| 长菜谱滚到底保存 | 顶部固定保存，正文独立滚动 | 编辑过程中始终能保存 |
| 管家写入自由文字 | 导入、助手、维护使用已有标签 ID | 避免近义标签持续增生 |

目录沿用已确认的 107 项：46 菜系、12 特性、49 方法；初始开启 24 项（2/8/14），菜系仅中餐与西餐开启。所有词条可开关、改名、删除；可添加自定义词条、维护别名和上级关系、合并同类型标签。批量操作作用于当前筛选结果或选择项。恢复默认仅重设内置词条开关，保留改名、自定义项和关联。

关闭标签保留菜谱关联；卡片可回退至已开启上级，详情仍显示原词条及「未显示」。删除为保留标识的停用，可撤销或从已删除列表恢复。合并在一个事务内迁移关联，阻止上下级循环。

## 数据与迁移

- 数据库 schema 15 → 16，迁移前按现有机制创建安全备份。
- `app_settings` 中使用 `recipe_tag_def:<ID>` 与 `recipe_tag_links:<recipeID>` 两类结构化记录。沿用现有命令事务、撤销、同步日志和备份链路，不另建只存在前端的标签库。
- 当前标签关联与配方版本分开。修改标签不会修改菜单绑定的历史配方。
- 原分类和自由标签中，明确匹配名称或唯一别名的转为稳定 ID；其余保留为待整理原词，可继续搜索，并能归入已有标签。旧配方分类保留兼容读取，但新菜谱界面不再维护它。
- 原管家 `tags` 写入命令和入口已移除；旧元数据只保留迁移记录，不再形成第二套活跃标签。
- 用户手工标签优先，自动维护不会覆盖；新建且尚未标注的菜谱仍可参与维护。开启新目录词条后，相关菜谱会重新进入增量检查。
- 云快照导出与恢复白名单均保留标签定义及关联；两份临时 SQLite 验证了定义修改、关联、合并和撤销的同步重放。
