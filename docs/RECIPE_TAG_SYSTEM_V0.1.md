# 菜谱标签系统：目录与交互初稿

2026-11-01。本轮完成资料检索、107 项机器目录和可操作检阅页，供确定标签范围与交互。尚未迁移 App 数据，也未把原有分类界面替换为新系统。初始化引导留到下一阶段。

直接打开 [标签系统检阅页](recipe-tags-review.html)，可查看卡片标签位置、组合筛选、搜索目录、逐项开关、批量操作、自定义标签及弹窗顶部保存。页面使用演示菜谱；所有修改仅留在当前页面，可导出检阅配置，刷新恢复初稿。

## 三个维度

| 类型 | 目录规模 | 初始开启 | 原则 |
| --- | ---: | ---: | --- |
| 菜系 | 46 | 2 | 中餐与西餐；地方和国际风味按需开启 |
| 菜品特性 | 12 | 8 | 精简、可理解的菜品属性；不把所有场景和食材也塞进来 |
| 烹饪方法 | 49 | 14 | 基础做法默认开启，细分与专业方法按需开启 |

菜系已从 104 项精简为 46 项：保留八大菜系、常见地方风味及主要国际菜系，移除温州、苏锡、金陵等过细分支，以及较少使用的国家和区域风味；需要时仍可自行添加。印度菜与墨西哥菜保留为独立入口，不保留南亚、拉美等额外分组标签。

这里的“全面”是可持续扩充的实用目录，不是世界各地饮食传统的穷尽清单。地域范围与文化风格允许重叠，目录关系用于检索，不能表达为唯一、排他的菜系谱系。

**初始开启共 24 项：**

- 菜系：中餐、西餐。
- 菜品特性：家常菜、快手菜、下饭菜、一锅出、少食材、可提前准备、功夫菜、创新菜。
- 烹饪方法：炒、煎、炸、蒸、煮、炖、焖、烧、烤、焗、凉拌、卤、煲汤、空气炸。

菜品特性中的融合菜、传统经典、适合冷冻备餐、分子料理默认关闭。融合菜和创新菜属于特性，可与川菜、法餐等菜系同时存在。专业做法如啫啫、低温慢煮、干式熟成、湿式熟成、球化、泡沫化均收录但默认关闭。初始开启数量和具体词条是本产品的设计建议，不是来源网站的默认值。

不增加第四组。早餐／午餐／晚餐仍由餐次表达，收藏仍为收藏状态，食材由配料表达。沙拉、汤羹、主食等菜式形态可在后续单独讨论，暂不硬塞为菜系或技法。口味、设备和饮食限制也不在本轮扩为独立标签组；空气炸保留为常用做法入口。

## 标签、显示与偏好分开

一份菜谱可以有多个标签；标签有稳定 ID，改名后不影响关联。建议通常标 3–6 项，卡片默认只展示 3 项，超出显示 `+N`。不同类型用克制的浅底区分，不为每个词条引入独立颜色或图标。

| 操作 | 对目录和菜谱的影响 |
| --- | --- |
| 开启 | 进入常用筛选及编辑候选；不自动标记菜谱，也不代表喜欢吃 |
| 关闭 | 从常用入口隐藏，已有关联保留；完整目录和菜谱详情仍可查看 |
| 删除 | 停用该词条并移除当前有效关联，不删除菜谱；用墓碑记录支持同步和撤销，历史版本继续保留 |
| 改名 | 更改显示文字，保留 ID；旧名称可保留为搜索别名 |
| 合并 | 将同类型重复项迁移到目标 ID，先展示关联数量；不能把不同含义仅因名字相似就合并 |
| 恢复默认开关 | 只调整内置标签的显示开关，保留用户自定义标签、改名和菜谱关联；不重置整个目录 |

正式版需支持内置和自定义标签的添加、编辑、删除、开关，批量操作支持搜索结果、整组和已选项目。批量删除展示影响数量，再确认；普通开关即时反馈，可撤销。检阅页为方便重复试验，另有“恢复检阅默认”，会重建整个演示目录，**它不等于正式版的恢复默认开关**。

**显示偏好与饮食偏好独立保存。** 开启川菜仅表示想在界面中使用这个标签，不能据此推断用户喜辣；关闭日本料理也不等于禁止推荐日料。后续初始化可同时询问“常用标签”和“饮食喜好”，但不能共用一个开关冒充两个含义。

## 层级与匹配

- 川菜可通过中餐筛出；淮扬菜可通过苏菜、江浙菜和中餐筛出。上级关系允许多个，用于用户检索，不强行做单父级树。
- 只保存实际选择的标签。选了淮扬菜，无需重复保存苏菜、中餐；筛选时展开上级关系。
- 卡片优先展示开启的具体标签；具体标签关闭时回退到已开启的上级。例如川菜未开启则显示中餐。无可用上级时不编造分类，详情保留原标签并标记为未显示。
- 同一类型多选用“或”，不同类型之间用“且”。“川菜或粤菜”＋“快手菜”＋“炒或蒸”可以组合，清除筛选一键恢复。
- 未标注表示三个维度均没有有效标签，不再作为真正的标签写入数据。单独提示“菜系待补充”比把所有缺项混成未分类更准确。
- 父级关闭不会连带关闭子级；开启子级也不自动将所有祖先铺到筛选栏上。祖先仍存在于目录，可作为路径和搜索词。

低温慢煮和低温熟成分别收录；啫啫不等于煲汤，普通腌肉前处理不必让每道菜都变成“腌制”。风味标签不作为过敏、宗教饮食、营养或食品安全判断的替代品。

## 界面与动效

| Before | After | Why |
| --- | --- | --- |
| 单排混放家常菜、西式料理、早餐等分类 | 保留全部菜谱、收藏等状态入口，旁边为菜系／特性／方法三个紧凑多选入口；选中项另显短标签 | 不把 24 个初始词条全铺成多行按钮 |
| 图片上压着一枚分类标签 | 标签移动到菜名下方、人数上方；最多 3 项，其余折叠 | 图片更完整，信息区有内容但不堆满文字 |
| 单选分类管理 | 同一管理弹窗内切换三个类型，搜索全目录，分节浏览，支持逐项与批量开关 | 保留现有管理入口的位置，避免新增永久页面 |
| 编辑长菜谱要滚到底部保存 | 菜谱编辑弹窗固定表头右上“保存”，正文独立滚动；校验失败滚动到首个问题 | 长短菜谱都能随时保存 |

鼠标点击选中标签即时改变底色和状态，不等待动画后再更新筛选。弹层用约 160–200ms 的轻微位移与透明度过渡；开关、标签状态反馈约 120–160ms。只动画透明度与 transform，不整页弹跳、不播放逐张卡片延迟入场。键盘操作立即响应；减少动态效果偏好时去掉位移。批量操作保留焦点和列表滚动位置。

检阅页的筛选、目录检索、批量操作、增改词条和卡片标签可交互；菜谱编辑只演示名称／标签与固定保存位置，步骤为占位内容，不声称实现完整 App 编辑器。检阅页不持久保存到应用。

## 接入现有 App 的方案

当前 `Recipe.category` 是单选字符串；自由标签保存在 `steward_meta:recipe:*` 的 `tags` 数组中，最多 12 个且没有类型。直接改一个下拉框无法承载新语义。

建议新增明确的数据模型：

```text
tag_definitions: id, group, label, aliases, broaderIds, enabled, deleted, builtinId
recipe_tag_links: recipeId, tagId, origin(user/import/ai/migration)
```

内置目录保持版本化，用户覆盖保存于本地数据库；更新目录只补新词条，不覆盖用户开关和改名。`recipe_tag_links` 为当前菜谱的组织信息，和配方修订分开；修改标签不改变周菜单绑定的配方版本。删除词条保留历史标识以解释历史，合并和撤销作为单次事务。接入时将定义与关联一起纳入现有命令、备份、复制／同步及撤销链路，不能只塞进暂存前端状态。

兼容旧数据采用增量映射：

| 旧内容 | 新处理 |
| --- | --- |
| 家常菜 | 菜品特性／家常菜；不因此自动判定为中餐 |
| 西式料理 | 菜系／西餐 |
| 早餐 | 保留原始迁移信息，不错误归入三个维度；继续可全文搜索 |
| 轻食沙拉 | 保留原词并列入待归组，不猜测低脂、低热量或菜系 |
| 自定义分类、旧自由标签 | 名称与别名明确匹配则映射；无法确定的保留原词进入待整理区，用户选择类型后转为正式标签 |
| 未分类 | 不创建对应标签；菜谱进入未标注视图 |

迁移不依赖在线模型、不批量删除原数据；本地事务成功后保留迁移记录。旧自由标签中出现的食材、口味和场景不自动塞入菜品特性，先保留再整理。库存分类／食材头像索引不在本轮修改范围内。

**统一替代管家的自由文字标签系统，不保留双轨写入。** AI 导入、聊天助手、每日管家维护共用标签定义与菜谱关联，只能提交已有 `tagId`；后端验证标签存在、类型正确、未删除，拒绝把任意字符串当作新标签保存。管家不再单独维护 `steward_meta` 下的自由 `tags` 数组，也不另起一个“AI 标签”入口。

管家优先选取已开启词条，并可按需检索完整目录；别名由程序映射为同一个 ID。明确属于某个关闭细分类时可提出“开启并标注”的建议，不能静默扩张标签栏。没有合适词条就留空或提交待确认的新增建议，不能自动造词。用户手动标签优先，AI 不覆盖。模糊的菜系、融合身份与主观属性保留建议，不强制补齐三个维度。

切换时同时移除旧 `save_tags` 自由字符串命令、维护任务中的自由标签输出与应用入口，旧数据只作为一次迁移输入；不能仅在提示词里要求“少生成自由标签”却仍保留后端写入通道。菜谱使用三维标签；食材／批次不套用菜系、做法标签，其旧自由标签写入也停用，现有食材分类和库位继续保留。确实需要保留的旧食材描述进入说明字段或迁移记录，不再形成第二套活跃标签。

实施顺序：目录与交互确认 → 定义／关联和迁移 → 编辑器／筛选／卡片 → AI 和历史兼容 → 备份、同步、撤销及实机验证。验收须覆盖别名、上级匹配、关闭保留关联、批量操作、长菜谱保存、旧分类迁移、重启与同步。当前只完成第一步的可检阅初稿。

## 来源与整理方式

查阅日期：2026-11-01。仅参考词汇和分类维度，自行整理目录、解释、默认开关及产品关系；没有复制网站整套分类或菜谱内容。完整字段见 [catalog.v1.json](../resources/recipe-tags/catalog.v1.json)。每个词条的 `provenance: curated` 表示产品人工整理，不冒充某个来源逐条认证。

- [美食天下：菜谱分类](https://m.meishichina.com/recipe/)：中文地方菜系、国际菜系和常见属性的参考。
- [下厨房：分类浏览](https://m.xiachufang.com/category/)：常用属性词，以及菜式、场景、食材不宜混为一个维度的对照。
- [China.org.cn：Eight major cuisines of China](https://www.china.org.cn/m/english/china_key_words/2024-08/29/content_117393720.html)：八大菜系与苏菜细分参考；检索摘要可读，原页打开超时。
- [Good Food：Cuisine recipe ideas](https://www.bbcgoodfood.com/recipes/category/cuisine-collections)：国际菜系浏览词参考；并非其全部内容的移植。
- [Great British Chefs：How to Cook](https://www.greatbritishchefs.com/how-to-cook) 与 [低温慢煮说明](https://www.greatbritishchefs.com/features/sous-vide-the-essential-guide)：做法与进阶技法参考。
- [DRY AGER：FAQ](https://www.dry-ager.com/en/faq/)：熟成相关术语，和控温烹调分别表达。
- [新华网：啫啫煲报道](https://www.xinhuanet.com/food/20250807/d8eb8d8ec30c413e8058861f8a11f338/c.html)：专门技法／风格词的用语参考。

重建检阅页：`node tools/recipe-tags/build-review.mjs`。生成脚本检查 ID 唯一、类型合法、上级引用有效且无环；运行时不联网读取目录。
