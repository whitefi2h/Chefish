# 离线操作记录

当前为增量同步的本地基础层。厨房操作会在保存业务数据的同一事务中记录待同步操作；没有增加自动同步开关，也没有上传或应用这些操作。现有手动云备份继续使用原有入口。

## 保存方式

数据库升级到 schema 12，升级前先保存 `pre-v12-*.sqlite3` 一致备份。新增 `local_sync_state` 保存数据库副本标识，`local_sync_outbox` 保存按本地序号排列的操作组。标识重启不变，完整恢复后重新生成，代表恢复后的新副本。

`db::execute` 的命令校验、业务写入、请求回执、数据版本增加和队列写入在同一事务内完成。队列保存失败时，库存、采购、菜单等写入和请求回执一起回滚。相同请求 ID 与相同内容重试时保留原回执，不新增操作组；同 ID 不同内容仍拒绝。

捕获使用当前连接的临时 SQLite 触发器，仅在业务事务执行期间启用；表名采用明确的业务表允许列表。捕获实际写入前后的整行 JSON，保留随机生成的对象 ID、精确十进制文本和行版本。单次采购入库、烹饪或批量命令整体保存为一个操作组。它们不能通过重放原始命令重新生成对象。

操作载荷使用确定性 gzip 压缩，并保存压缩字节的 SHA-256。记录包含格式版本、数据库结构版本、操作 ID、副本 ID、操作前后本地数据版本、按写入顺序排列的行变化与允许同步的设置变化。队列序号独立于本地数据版本；只修改通用设置时数据版本可增加，但不生成同步操作。

## 内容范围

| 内容 | 本地队列 |
|---|---|
| 菜谱、版本、食材与调料、图片、分类 | 记录实际行变化 |
| 库存与事件、菜单、采购与收货、烹饪及手记 | 记录整个事务结果 |
| 采购备忘、调料隐藏状态、撤销所需日期原值 | 记录允许的设置键变化 |
| 默认人数、口味、忌口、厨具 | 只记录这四项的变化 |
| 启动页、发送快捷键、自动备份开关 | 排除；仅修改这些选项不入队 |
| 聊天、模型密钥、账户凭据、未知设置键 | 排除 |

AI 提案在副本中的试运行不会修改真实队列；确认执行后才随真实事务入队。只读查询、聊天保存和启动时迁移不补记为厨房操作。已有厨房通过后续首次绑定基线处理，不伪造为一系列新操作。

## 恢复与兼容

完整本地备份保留原队列，便于恢复前证据留存；实际恢复时先保存安全备份，再重置恢复副本的队列和副本标识。失败时恢复原数据库及原队列。当前恢复是明确替换厨房数据，不把恢复操作加入普通增量组。

手动云备份在暂存副本中移除本地队列、副本标识和相关 SQLite 序号，再 VACUUM 清理释放页；不会携带本机操作历史队列。厨房业务历史仍按原规则保留。下载恢复后使用新的副本标识。

云端备份权限接受 schema 1–12，继续兼容旧备份。旧程序不能打开 schema 12 数据库或恢复其备份；如需回退程序，应使用升级前备份，并另外保留升级后的最新数据。

## 验证与下一步

临时数据库测试覆盖表清单完整性、生成 ID 与精确值、重启、重复提交、批量失败、队列写入失败、采购与烹饪完整组、AI 试运行隔离、设置隐私、恢复重置与安全备份、schema 11 升级。云备份测试额外检查副本标识字节与队列内容被清除。具体结果见 [验证记录](sync-outbox-validation.json)。

只读 IPC `kitchen_sync_status` 返回当前副本标识、待处理操作数和压缩载荷总字节数，供后续状态界面接入；当前界面不把它显示为已启用自动同步。

尚未实现账户归属绑定、云端序列和游标、队列确认与压缩保留策略、远端重放及冲突处理。目前队列留在本机并随操作积累，不能视为云端已保存。下一阶段完成这些约束后，才能安全消费队列并开启自动同步。
