# 初始化与数量显示：实施和验收

日期：2026-11-03。实施前方案见 [初始化流程实施方案](ONBOARDING_PLAN_20261103.md)。版本保持 2.0.0；未提交、推送或替换已发布 Release。

本页记录第一轮功能实现及其历史验收。首次布局未获用户认可；当前呈现、尺寸、动画与第二轮检阅结果以 [紧凑初始化重设计](ONBOARDING_REDESIGN_20261103.md) 为准。下文旧版截图不作为当前视觉验收证据。

## 已实现

| Before | After | Why |
| --- | --- | --- |
| 采购需求和摘要直接展示六位小数 | 需求、库存、缺口、待买、详情、复制文本，以及首页、周菜单、助手摘要统一最多一位小数；去掉末尾零 | 数量更容易阅读，降低换行占用 |
| 极小非零数量可能舍入成零 | 显示 `<0.1` | 避免误示为无需采购 |
| 个性化配置散在设置中 | 增加欢迎、模型、偏好、菜系、管家、账户、完成七步向导 | 首次使用时按顺序配置，每步均可跳过 |
| 偏好只能逐项填写 | 可主动输入一段习惯，由已配置模型整理为草稿，检查并应用后继续编辑 | 保留用户对长期偏好的控制 |
| 长表单容易失去操作入口 | 固定进度和底部操作，正文独立滚动；保存期间锁定编辑和切步 | 减少误操作和未保存输入丢失 |
| 管家修改后有两颗底部主按钮 | 修改后仅显示现有保存按钮 | 保持明确的当前操作 |

原始数量、数据库精度和采购计算保持不变，购买输入保留实际数量。空白厨房首次打开向导；已有厨房不强制弹出，可从“厨房设置 → 通用 → 重新开始初始化”进入。重新进入预填现有配置，不清空厨房。

当前切步使用 220ms 淡入和 12px 位移；键盘切步及减少动画模式不播放该动画。标题接收键盘焦点，底部操作保持可见。关闭或跳过不保存当前未提交草稿；已明确保存的配置保留。进度存于本机 WebView 存储，意外退出后可继续步骤。

## 数据和服务边界

- 复用现有偏好、标签定义、模型配置、管家设置及账户服务。未增加数据库迁移或新依赖。
- 新原生命令 `kitchen_onboarding_interpret` 只返回偏好草稿，不写数据库、不执行厨房工具。人数和菜系 ID 经过校验；不把未陈述的信息推测为过敏、疾病或饮食禁忌。
- 模型接收本次用户主动填写的描述和现有标签目录，不读取厨房库存或烹饪记录。选择菜系只调整菜系标签开关。
- API 密钥沿用 Windows 凭据管理器；账户密码只用于本次认证，不写流程进度。云账户初始化不自动上传、绑定或替换厨房。
- 管家及开机自启动沿用原开关；全跳过不会启用。
