# 初始化流程实施方案

先修复采购数量显示，再实现初始化。沿用现有字体、橙绿配色、统一设置和原生服务。

## 数量显示

采购清单的需求、库存、缺口、待买、详情、复制文本及首页采购摘要统一最多一位小数，去掉末尾零；非零但不足显示精度时显示“小于 0.1”。不舍入数据库、计算结果或购买表单里的实际数量。

## 初始化路径

| 步骤 | 内容 | 保存方式 |
| --- | --- | --- |
| 欢迎 | 说明个性化设置可跳过、稍后可重新进入 | 本机记录流程进度 |
| 模型连接 | 选择服务、模型、API key，保存和测试连接 | 复用模型配置，密钥仍由 Windows 凭据管理器保存 |
| 饮食偏好 | 人数、口味、忌口、厨具、餐次展示；可自愿调用模型整理自然语言 | 模型只生成可编辑草稿；确认下一步才保存现有偏好 |
| 常吃菜系 | 从统一目录选择常吃菜系，按需展开地方风味 | 复用标签定义保存命令，只调整菜系开关 |
| 厨房管家 | 主动任务、免打扰、自启动及时间安排 | 复用现有管家设置和保存逻辑，首次不默认启用 |
| 云账户 | 注册、登录与邮箱验证引导 | 复用现有账户能力；不自动上传、加入或覆盖云厨房 |
| 完成 | 已完成与跳过步骤摘要，进入厨房 | 本机记为完成，设置可再次打开 |

空白厨房首次加载完成后自动显示；已有厨房不强制弹出。在通用设置提供“重新开始初始化”，重新进入时预填现有配置，不重置数据。关闭、跳过当前步均不提交当前未保存草稿；已明确保存的配置保留。意外关闭应用后可从记录的步骤继续。进度只在本设备保存，不写入同步偏好；密钥和账户密码不进入流程进度或普通备份。

## 交互与边界

- 居中向导、轻量进度条、稳定底部按钮、内容区独立滚动。切步短距离淡入，遵循系统减少动画；键盘操作不强制播放切步动画。
- 每步均可跳过或返回；保存失败保留输入并停留原步，不假报完成。网络动作显式触发，忙碌时禁止重复提交和切步。
- AI 偏好整理只接收用户本次主动输入，不访问厨房库存，不写数据，不推断过敏或疾病。返回值经原生校验后展示，用户仍可修改。
- 不增加依赖、主题或永久导航。不修改库存计算、采购精度、已有 AI 菜单规划和同步规则。

## 验收

数量格式单元测试；初始化的首次展示、全部跳过、重启恢复、重新进入、偏好保存、菜系开关、保存失败、AI 草稿和密钥保存边界；现有设置与采购回归。以隔离数据在多尺寸和减少动画模式截图检查。最后构建 EXE 和 NSIS，不自动提交或更新 Release。区分浏览器合成服务、原生本地测试和真实第三方服务验收。
