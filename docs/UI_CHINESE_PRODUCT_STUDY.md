# 中文效率产品布局研究与 Chefish 调整建议

2026-11-01。研究范围：官方产品页面、帮助中心中的中文桌面界面图，以及有赞的设计规范。对照 Chefish 最近保留的 Windows WebView2 截图。此文提出设计建议，本轮未修改应用代码。

当前最影响协调性的三个问题：**工具区纵向层级偏多、辅助信息偏重、重复内容缺少统一的对齐节奏**。可以保留思源黑体和现有橙绿配色，先把页面中信息的主次与间距理顺。

用户后续修正：库存筛选是核心功能，必须完整保留在列表上方；不采用压缩、折叠或下移筛选的方向。搜索框收窄后移至“我的食材”标题右侧，恢复管理分类、自动分类的按钮辨识度，删除“直接调整数量与库位”说明。其余同意的调整及动态状态字号检查见 [本轮实现记录](UI_COHERENCE.md)。

## 1. 滴答清单：用行和分组承载内容

在官方 Windows 示例图中，导航、清单、详情分别处于稳定的纵向区域；各区标题贴近本区内容。清单内部依靠分组标题、细分隔线和一致的行结构组织，任务名称在左、时间在右、数量退为浅色。选中项才出现明显底色，普通项目没有逐项套卡片。

这使视线沿固定位置扫描：先读任务，再看时间。标题能突出，同时整屏不会处处都是强调文字。[来源：滴答清单 Windows 官方页面](https://beta.dida365.com/windows?language=zh_CN)。

**适用于 Chefish：**采购清单、首页右侧提醒和常备调料。保留现有面板，将面板内部统一为“头像／名称／数量或状态／操作”的行结构。不能照搬其多级侧栏；Chefish 现有五个导航足够。

![滴答清单官方 Windows 展示图](screenshots/chinese-ui-research/dida-windows.png)

## 2. 飞书日历：把控制和内容放在明确的两层

官方帮助图中，日期切换、今天按钮和视图切换集中在上方；下方直接进入周历。星期、日期数字、时间轴采用不同的视觉层级；细网格负责维持位置关系，当天用局部强调定位。无需给每个日期再套完整面板。[来源：创建日程并邀请参与者](https://www.feishu.cn/hc/zh-CN/articles/360024861134-%E5%88%9B%E5%BB%BA%E6%97%A5%E7%A8%8B%E5%B9%B6%E9%82%80%E8%AF%B7%E5%8F%82%E4%B8%8E%E8%80%85)。

**适用于 Chefish：**周菜单的周切换、日期范围与现有采购入口组成紧凑工具区，七日周历随后展开。日期数字承担定位作用，星期和月份退后。保留餐次、菜卡和灵感栏，压缩它们之间重复的外间距。

首页的小周历可以继续尝试衬线数字，但日期只承担一个层级；不将衬线字体扩展到库存数量和采购单位。

![飞书日历官方帮助图](screenshots/chinese-ui-research/feishu-calendar.png)

## 3. 飞书多维表格：让字段位置稳定

官方示例中，添加、筛选、分组和排序集中在同一工具带；字段名在表头，记录在下方重复同一行结构。文本、状态、人员各有固定列；彩色主要出现在有语义的状态与头像中。列操作收在字段菜单中，减少记录本身的装饰。[来源：使用多维表格字段](https://www.feishu.cn/hc/zh-CN/articles/541575577400-%E4%BD%BF%E7%94%A8%E5%A4%9A%E7%BB%B4%E8%A1%A8%E6%A0%BC%E5%AD%97%E6%AE%B5)。

**适用于 Chefish：**库存最值得借鉴的是稳定的列宽、数字位置和工具区组织。名称列容纳两行，数量列给数字和单位预留固定空间，日期格式一致，状态与操作保持各自的列。保留常显的加减和库位控件，不能为了整洁隐藏必要操作；也无需复制其密集纵向网格和复杂字段菜单。

![飞书多维表格官方帮助图](screenshots/chinese-ui-research/feishu-table.png)

## 4. Teambition：容器表达分组，卡片表达对象

官方研发协作示意中，浅灰区域表示工作分组，白色小卡表示任务对象，列标题在共同的顶部横带中。容器和内容具有不同的表面，不需要层层白卡来重复表达分组。[来源：Teambition 研发团队官方页面](https://www.teambition.com/agile/)。

**适用于 Chefish：**主内容使用白面板，辅助区域使用浅底，普通行依靠对齐和分隔。首页下一餐可以突出照片；提醒和采购摘要应减轻标题、标签及边框的重量。保留面板位置与顺序，避免所有面板获得同等视觉强调。

![Teambition 官方研发协作示意](screenshots/chinese-ui-research/teambition-board.png)

## 5. 中文排版的直接参考：有赞

有赞的 PC 规范以 14px 为主字号，推荐配 20px 行高，并区分标题、正文、辅助信息和数字的字重。这是其设计体系的取舍，不能据此认定其他产品采用相同参数。[字体规范](https://design.youzan.com/visual/font.html)。其间距规范采用 4、8、16、24、32 等有规律的刻度，以统一模块和元素的距离。[间距规范](https://design.youzan.com/pattern/spacing.html)。

对 Chefish 的启发是：已选的 Semibold 标题与 Medium 主信息可以保留，但批次、说明、计数和工具文字应另设层级。上一轮广泛套用 Medium，使辅助信息也有较强存在感；继续整体缩小字号难以解决这一点。

## 6. 对照当前实机，建议改什么

下表属于 Chefish 的设计判断；参数是待截图比较的起点，不是从竞品截图测得的数值。

| Before：当前表现 | After：建议方向 | Why：原因 |
| --- | --- | --- |
| 库存标题、关注区、面板标题、搜索、两行筛选依次下压，数据开始较晚 | 保留区域顺序；收紧关注区、标题与工具区之间的距离；搜索和操作成一组，筛选成另一组 | 减少进入第一条数据前的纵向层级，同时保留全部入口 |
| 名称、数量、日期、状态各自可读，但组合后视觉重量不均 | 为数量、单位、日期、状态设稳定列槽和共同中心线；数量内部右对齐，数字使用等宽数字特性 | 字号相同仍可能因为位置、字宽和颜色显得不协调 |
| 批次日期、说明与主要信息都偏重 | 名称和主数值保留 Medium／Semibold；辅助信息试 Regular，与现有 Medium 并排比较 | 保住已认可的主信息清晰度，恢复层次 |
| 首页右侧区块标题接近重点菜名的视觉重量 | 下一餐保持主视觉；右侧标题从约 17–18px 起试，列表内容保持清晰，缩短标题到首行的距离 | 提醒与采购摘要承担快速扫读，避免和下一餐争夺注意 |
| 采购右侧统计连用三块彩底，复制与导出又各占宽按钮 | 保留原面板与入口；重点突出待买数量，其余统计改轻量行，辅助按钮统一低强调样式 | 减少小区域中同时争夺注意的元素 |
| 菜谱顶部标题、搜索、分类各自占较宽松的纵向空间 | 保留最大化四列／普通窗口三列、4:3 封面和菜名右侧浅色按钮；微调工具区间距及卡片文字对齐 | 菜谱已有内容感，继续大改卡片收益较小 |
| 周历日期、菜卡、空状态的间距尺度不一 | 顶部控制集中；日期、菜卡标题、元数据分别使用固定的层级；空状态沿同一网格定位 | 减少跨单元格扫描时的跳动感 |

## 7. 下一轮样板的优先顺序

1. **库存：**先解决工具区纵向层级与数据列对齐；同一窗口、同一数据下比较前后。
2. **首页与采购：**减轻辅助面板，统一列表节奏；首页保留食物图片带来的温度。
3. **周历与菜谱：**以共同的间距和文字层级收尾，保持已确认的结构与列数。

交互检查应与样板同时进行：数量点击立即反馈、筛选后工具区不跳动、轮播可连续操作、拖放结果及时出现。上述静态官方图只提供布局证据，不能据此声称已测得竞品的动效时长或操作延迟。

证据边界：本次未登录竞品账号、未测试其完整客户端。官方图可能来自不同版本；飞书两张帮助图带有教程强调遮罩，不能拿遮罩后的灰度测量其实际配色。保留的图片只用于本地设计检阅，不作为 Chefish 内置素材。此次不改变功能、导航、数据库、AI、版本或 Release。
