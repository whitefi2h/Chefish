# 初始化：固定外框与偏好分步

本轮依据用户四张新批注，取代第二轮中“欢迎、完成缩小”和“描述折叠”的安排。

| Before | After | Why |
| --- | --- | --- |
| 欢迎、配置、完成使用不同尺寸 | 全程共用 600×552 CSS px；小窗口统一受视口减 40px 限制 | 切步时外框和页脚位置稳定 |
| 自由描述折叠在偏好表单上方 | 独立描述页，随后进入核对表单页 | 避免展开后拉长页面 |
| 识别草稿需再次点击应用 | 点击“识别并继续”，只把明确识别的字段填入下一页 | 直接核对，未提及字段保留默认或已有值 |
| 模型、菜系、管家标题下重复说明 | 删除批注划掉的三段说明 | 减少重复文字 |
| 初始化模型页有高级参数入口 | 初始化仅显示服务、模型名称、密钥；完整设置仍保留高级参数 | 首次配置更简洁 |

描述为空可手动填写；跳过描述不调用模型。识别失败留在描述页，原输入保留。核对页仍需用户点击“保存并继续”才写入长期偏好。餐次等无关选项保留原值，菜系选择继续沿用受控目录。进度仍为五类配置，偏好的两页都属于第二步，不改变原进度编号。

验证：TypeScript、ESLint 与 6 项不同的相关浏览器测试通过，覆盖全跳过、AI 识别后核对编辑、未提及餐次的默认状态、未提及人数/忌口/厨具保留人工编辑值、保存失败保留输入、账户及模型原保存流程。全部展示阶段在 571×400、1000×700、1280×800、1440×900、1920×1080 五种 CSS 视口逐页测量，外框宽高差小于 1px；额外检查描述页到核对页的宽高相等，底部操作在视口内。短窗口仅滚动正文。40 张截图的用例与打包并行时曾超过 30 秒，已将该截图用例上限改为 60 秒并单独重跑通过（26.2 秒），布局断言未放宽。

本轮截图使用浏览器合成数据：[描述页](screenshots/onboarding-round3/1000-700-description.png)、[核对页](screenshots/onboarding-round3/1000-700-step-2.png)、[模型页](screenshots/onboarding-round3/1000-700-step-1.png)。本轮未重新进行真实模型调用、云注册或 Windows 登录自启动验收。

后续收窄：依据用户最新批注，将统一宽度从 680px 改为 600px（约收窄 12%），高度保持 552px 及原视口上限。删除核对页标题下的说明；移除厨具输入框的 36px 单行高度覆盖，沿用 58px 两行文本框。正文保留独立滚动，页脚固定。仅重跑受影响的五尺寸全流程检查，并核对两行文字所需行高与内边距，检查通过；ESLint、TypeScript 随打包检查。此轮截图为浏览器合成数据，见 [核对页](screenshots/onboarding-round4/1000-700-step-2.png) 和 [开启管家后的布局](screenshots/onboarding-round4/1000-700-step-4.png)。
