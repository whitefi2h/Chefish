# 后续开发方向

更新：2026-10-25。用户已确定先做功能，UI 另行制作多版预览讨论；以当前界面为基础，接近原型的现代质感，不直接替换现有操作布局。

本地备份恢复和用餐偏好已完成首版，并集中在左下角设置弹窗。用户最新授权优先推进 Firebase 云同步，参考项目为 `E:\zenfish`；食材名称表与烹饪回顾暂留后续。

1. **备份与恢复**：数据库一致快照与图片打包；选择路径、完整性校验、恢复预览、自动备份保留策略；恢复可回退，凭据不混入普通备份。
2. **用餐偏好**：默认用餐人数同时用于菜谱详情初始展示份量、手动配餐和 AI 配餐；保留配方原标准人数与用量，不改写历史菜单。口味、忌口、厨具等采用自由文本，可修改清除，进入 AI 上下文，当次明确要求优先。
3. **食材名称统一**：内置覆盖常见中文食材的规范名与别名表，如番茄 / 西红柿。导入自动使用规范名并保留来源原文；手动输入别名时提示是否改用规范名，允许保留原名。只自动归并明确同义词，不把不同形态或品种强行合并；已有数据合并需预览数量、单位和引用变化。
4. **烹饪回顾**：结合实际烹饪记录和厨房手记生成可编辑回顾，也允许自由编写。区分实际做过、仅计划和仅手记，向 AI 提供近期烹饪和调整意见以减少重复配餐。记录自己的事实，不自动把笔记当作完成烹饪或触发库存扣减。
5. **导出与 Windows 交付**：菜谱与清单导出；已提供 Windows x64 安装包，后续补齐升级卸载数据保留验收，再评估签名和自动更新。

图片导入、库存持久化、菜单采购烹饪闭环、AI 业务提案、聊天保存和调料管理已经实现，不再列作待开发；它们的稳定性修正应单独记录。

AI 连续任务按用户现有体验不再作为独立新功能安排，只修复实际遇到的问题。做饭模式保留为低优先级候选。

## Firebase 云备份与多设备同步

多设备同步首版已完成：账户首次连接、含图片基线、离线操作队列、后台上传拉取、原生事务重放和冲突处理。独立免费项目与真实 Firebase 双原生临时库传输通过检查，没有启用付费 Storage。详见 [账户与多设备同步](CLOUD_SYNC.md)。

后续维护集中在云端占用统计、保留策略、历史压缩与两台实体设备的长期体验。密钥、聊天与通用设置继续留在各设备。食材名称表、烹饪回顾与全局 UI 调整仍保留原顺序，未在本次扩展。
